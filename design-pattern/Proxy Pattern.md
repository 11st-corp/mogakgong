# 프록시 패턴

## 인터페이스 기반

프록시 패턴은 원본 클래스를 변경하지 않은 상태로 프록시 클래스를 도입해 새로운 기능을 추가하는 것이다.

이 때, 핵심은 원본 클래스와 관련없는 새로운 기능(비즈니스 로직이 아닌)

원본 코드에 부가 로직을 추가하면 관련 없는 코드가 한 곳에 들어있게 되며 교체 비용이 늘어난다.

이를 위해 인터페이스를 기반으로 프록시 패턴을 구현할 수 있다.

프록시 클래스의 부가 로직 수행 -> 원본 클래스의 비즈니스 로직 호출

## 상속 기반

상속 기반의 프록시 패턴을 사용하는 경우에는 원본 클래스의 모든 메서드를 구현해야한다는 단점이 있고 기능 추가가 많은 경우 필요한 모든 클래스의 프록시 클래스를 생성해야한다.

이를 해결하기 위해 리플렉션 기반의 동적 프록시를 적용할 수 있다.

코드를 실행하는 도중 원본 클래스에 대한 프록시 클래스를 동적으로 생성하고 코드 내의 원본 클래스를 프록시 클래스로 대체하는 것을 말한다.(Spring AOP의 내부 구현이 해당 방식으로 동작)


## 프록시 패턴의 활용도

1. 비즈니스 로직과 관련없는 요구 사항 개발에 활용
   a. 모니터링, 통계, 인증, 트래픽 제한, 트랜잭션, 멱등성, 로깅
2. RPC에서 프록시 패턴을 적용 가능
3. 캐시에 프록시 패턴을 적용할 수 있음
